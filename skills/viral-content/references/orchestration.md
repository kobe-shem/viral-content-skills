# Run a content operation

For a short rewrite, one writer can do the work. For a new research system or a substantial creative batch, split independent work while keeping one creative owner accountable for the result.

## Model and role allocation

Use the strongest available judgment model for the brief, concept selection, source conflicts, script critique and final synthesis. This package was developed with GPT-6 Astra in that role. Routine collection, transcript cleanup, indexing, deduplication and source lookup can use a lower-cost model such as GPT-5.6 Sol. Model names are runtime choices, not hard dependencies of the skill.

Give each research worker a concrete source lane and output contract: creator identity, date range, paid/organic/teaching scope, item/cost cap, raw storage location, coverage fields and unresolved questions. For file work, give explicit ownership and tell workers to preserve others' edits. Keep credentials in the environment that owns them.

The creative owner reviews the evidence needed for the decision. They resolve conflicting teachings, distinguish the creator's assertion from observations, check material claims and choose what transfers. A neat worker summary does not substitute for the underlying clip, timecoded transcript or actual account result when the conclusion depends on it.

For independent evaluation, isolate the writer from hidden feedback and the judge from version labels. Preserve failed runs and disagreements. Re-running until the favored version wins is not a benchmark.

## Research to production

1. **Brief:** identify the audience situation, outcome, available facts and production capacity. If interviewing, `grill-me` captures the speaker's actual experience and beliefs; turn that material into a project profile and idea pool.
2. **Research:** answer demonstrated creative questions with existing evidence first. Collect creator/competitor records, then matched strong/typical/weak original examples. Save useful customer-language findings and uncertainties.
3. **Concepts:** separate different audience/angle/offer choices from format or hook variations. Develop the promise, progression, payoff and opening picture before selecting.
4. **Script:** write the exact requested deliverable in the speaker's register. Review scope, meaning, rewards and claims. Produce compatible hook variants only after the body is sound.
5. **Direct:** specify first-frame action, camera, text, performance, sound, reveal and closing hold. Attach actual proof assets or clearly labeled illustrative requirements.
6. **Produce/edit:** hand the plan to the production skills or an editor. Ingest actual media, measure timing, render, and inspect the finished audiovisual result. Keep approval and asset versions aligned.
7. **Learn:** record exact editorial corrections and separately ingest comparable audience/business outcomes. Choose the next test and promote only scoped lessons supported by evidence.

The skills reduce coordination and preparation work. The speaker's real expertise, the truth of product claims, usable footage and outcome measurement still need actual inputs.

## A practical weekly loop

At the start of a batch, review recent comparable results and the open research questions. Select a manageable set of distinct concepts and keep one explicit reason for testing each. Film compatible variants together; name versions so the final ad can be traced to its idea, hook, body, CTA and edit.

After publication, append snapshots at consistent ages appropriate to the platform and business. For paid work include qualified outcomes and downstream quality, not only clicks. When reviewing, point to the exact beat or mechanism that the next edit tests. Carry forward successful evidence and unresolved alternatives. Schedule recurring collection only when requested; a weekly process description does not itself create an automation.
